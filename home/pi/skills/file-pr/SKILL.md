# File PR

Generally follow the repos existing PR style and conventions.
Make the title human-readable, so don't throw in jargon and implementation details in there,
but something like a benefit.

For descriptions, give a simple explanation about the problem based on the prompt or issue
that was in the prompt, then explain the solution. Do not add how it's tested with trivial things
like cargo fmt or that the tests ran.
